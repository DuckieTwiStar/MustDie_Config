# MustDie_Config

Конфіги гри MustDie (Roblox). Гра читає їх сервером (`CoreServer.ConfigService`) за raw-посиланням:

```
https://raw.githubusercontent.com/DuckieTwiStar/MustDie_Config/release/<папка>/<ім'я>.json
```

Гра читає гілку **`release`**, а не `main`. Працюємо й комітимо в `main`; у гру зміни потрапляють лише після «просування» (див. розділ «Гілки: main і release»).

Джерело чисел: GDD MustDie, вкладка «Тест балансу». Кожна збережена версія балансу має id `BAL-XXXX`; він стоїть у `meta.version` кожного файлу. Знімок версії лежить також на Google Диску (папка `Balance`).

## Структура

```
lobby/                  конфіги лобі (магазини, щоденні нагороди, лідерборди, портали)
  items.json            той самий вміст, що rooms/shared/items.json
rooms/
  shared/               спільне для всіх кімнат
    rules.json
    enemies.json
    traps.json
    weapons.json
    weapon_upgrades.json
    leaderboards.json   той самий вміст, що lobby/leaderboards.json
    items.json          каталог предметів (іконка, назва, опис), той самий вміст, що lobby/items.json
  room1/                Room 1 (один спавнер, хвилі на 1 гравця, множники > 1)
    room.json
    zones.json
    waves.json
    players.json
  room2/                Room 2 (два спавнери, хвилі на 4 гравців, множники < 1)
    ...                 ті самі чотири файли
assets/icons/          вихідні PNG іконок (512x512, прозорий фон); гра їх не читає, у грі працює rbxassetid із items.json
docs/prices.md          ціни лобі: розблокування зброї, розблокування і прокачка пасток
tools/validate.py       перевірка перед комітом (так само її запускає GitHub Actions: .github/workflows/validate.yml)
```

### Що гра зараз реально читає

Не всі поля й файли в репозиторії підключені до коду. Зміна непідключеного поля нічого не змінить у грі.

| файл | читає гра | примітка |
|---|---|---|
| shared/rules, enemies, weapon_upgrades, run_rewards | так | |
| room.json | лише `base_hp` і `door_timer` | `spawners` (id, mode, cooldown) гра не читає: спавнери беруться з тегів `EnemySpawn` на карті |
| waves.json | так | `wave_delay` береться з першого рядка хвилі, тому в одній хвилі він має бути однаковим (перевіряє validate.py) |
| players.json | так | `hp_mult`, `count_mult`, `reward_mult` (нагорода за вбивство множиться на `reward_mult`) |
| zones.json | **ні** | довідкові дані для розрахунків балансу; маршрут задають `PathNode` на карті |
| items.json | **поки ні** | каталог готовий і перевіряється, підключення до коду пакетів: наступний крок |
| shared/weapons.json, shared/traps.json | **ні** | зброя й пастки вшиті в код пакета; ціни лобі див. `docs/prices.md` |

Якщо конфіг не вдалося завантажити (тимчасова помилка GitHub, не 404), сервер кілька разів повторює запит, далі працює на вшитих запасних значеннях і пробує знову кожні 30 с. У цей час `TD_State` має атрибут `ConfigDegraded = true`. Вшиті значення навмисно нейтральні й не збігаються з балансом ні однієї кімнати: це аварійний режим, а не копія Room 1.

Кімната читає кожен конфіг так: спершу `rooms/<roomId>/<ім'я>.json`, якщо його немає (404), то `rooms/shared/<ім'я>.json`, далі вшитий default. Файл кімнати **повністю замінює** спільний, злиття полів немає.

## Правила формату

1. UTF-8, коректний JSON: без коментарів, без кінцевих ком, подвійні лапки.
2. Корінь файлу це об'єкт: `{ "meta": {...}, "<ім'я>": ... }`. Ключ даних збігається з іменем файлу.
3. `meta`: `version` (`BAL-0003`), `exported_at` (дата `YYYY-MM-DD`), `note` (один рядок, що це за файл).
4. Колекції це масиви об'єктів з полем `id`. Числових ключів об'єкта не використовуємо. Порядок задає поле (`order`, `wave`, `level`), а не позиція в масиві.
5. `id`: `snake_case` (малі літери, цифри, `_`), унікальні в межах файлу (у пастках унікальна пара `id` + `level`), стабільні: після публікації не перейменовуються.
6. Числа числами, без одиниць у значенні. Відсутнє значення = відсутній ключ, не `null`. Булеві `true`/`false`.
7. Посилання між файлами за `id`: `waves.enemy_id` → `enemies.id`, `waves.spawner_id` → `room.spawners[].id`, `weapon_upgrades.weapon_id` → `weapons.id`.
8. Тексти для гравця: `name_en`, `name_uk`. Нова мова = новий ключ `name_xx`.
9. Поля, потрібні лише симуляції балансу, сюди не кладемо. Виняток: `zones.length` (див. нижче).
10. Секретів і особистих даних не кладемо: репозиторій публічний.
11. Кожне число з GDD, що впливає на гру, живе в конфігу і ніде більше. Нове число = нове поле тут і рядок у цьому README.
12. Геометрія карти лежить у Place. Зони, спавнери, двері описуються тут лише за `id`; у Place є об'єкти з тим самим `id` в атрибуті або тегу.

### Одиниці

| Величина | Одиниця |
|---|---|
| частки, шанси, броня, множники падіння | частка від 0 до 1 (`0.25` = 25%) |
| час | секунди |
| відстань, радіус, розмір | studs |
| швидкість | studs/с |
| гравітація снаряда | studs/с² |
| кути | градуси |
| ціни в `rooms/` | віспи (валюта забігу; у коді поля зветься `cost`/`reward`/`start_coins`) |

## Файли `rooms/shared/`

### rules.json → `rules` (об'єкт)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| start_coins | int | віспи | ≥ 0 | так | віспи кожного гравця на старті забігу |
| refund_share | number | частка | 0..1 | так | яка частка віспів повертається за знесену пастку |
| reward_mode | string | — | `each` / `split` / `killer` | так | хто отримує віспи за вбивство: кожен повністю / поділ / лише вбивця |
| ricochet_falloff | number | частка | 0..1 | так | частка урону, що лишається після кожного рикошету |
| cell_size | number | studs | > 0 | так | розмір клітинки сітки пасток |
| restart_delay | number | с | ≥ 0 | так | пауза після кінця забігу перед рестартом |

**Дебаг-меню (`rules.json` → `debug`, окремий ключ поруч із `rules`)**

```json
"debug": { "enabled": true, "user_ids": [11708066498, 11744693964] }
```

Дебаг-меню (+віспи, розмір команди) у справжньому клієнті Roblox (ПК і мобільний) бачать лише ті, чий UserId є в `user_ids`, і лише коли `enabled` дорівнює `true`. У Studio дебаг доступний завжди. Рішення приймає сервер; відсутній ключ, помилка завантаження чи неправильний формат означають «вимкнено».
**Перед публічним релізом** поставити `"enabled": false` (або прибрати ключ `debug`), коміт у `main`, потім `promote-release`. Пекеджі оновлювати не треба: сервери підхоплюють зміну за кілька хвилин. Поточний список: Женя (`DuckieTwiStar`), Степанов (`Choorack345`).

### traps.json → `traps` (масив, рядок на пару `id` + `level`)

Розблокування і рівень пастки зберігаються в профілі гравця (купуються в лобі, ціни в `docs/prices.md`). У кімнаті пастки лише встановлюються.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `snare`, `energy_wall`, `turret`; збігається з `id` предмета в магазині лобі |
| level | int | — | 1..N без пропусків | так | рівень пастки |
| order | int | — | ≥ 0 | так | порядок у вікні пасток (менше = раніше) |
| name_en, name_uk | string | — | — | так | назва |
| mechanic | string | — | `snare` / `wall` / `turret` | так | тип механіки |
| placement | string | — | `floor` / `wall` | так | куди ставиться |
| cost | int | віспи | ≥ 0 | так | ціна **встановлення** пастки цього рівня в кімнаті |
| damage | number | за удар; для `wall` за секунду | ≥ 0 | так | урон |
| cooldown | number | с | ≥ 0 | ні | перезарядка капкана |
| hold_time | number | с | ≥ 0 | ні | скільки капкан тримає ворога |
| fire_interval | number | с | > 0 | ні | інтервал пострілів турелі |
| range | number | studs | ≥ 0 | ні | радіус турелі |
| default_owned | bool | — | — | ні | `true` на рівні 1 пастки, яка є в усіх без покупки |

### weapons.json → `weapons` (масив)

Розблокування зброї в профілі гравця (лобі, ціни в `docs/prices.md`). Перед забігом гравець обирає зброю зі своїх наявних.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | збігається з `id` предмета в магазині лобі |
| order | int | — | ≥ 0 | так | ранг: більше = вище у вікні вибору перед забігом; у магазині лобі навпаки; слоти клавіш 1..N від меншого до більшого |
| default_owned | bool | — | — | ні | `true` = є в усіх без покупки |
| name_en, name_uk | string | — | — | так | назва |
| damage | number | — | ≥ 0 | так | урон за удар/постріл (дробовик: за одну дробину) |
| attack_interval | number | с | > 0 | так | пауза між атаками |
| range | number | studs | ≥ 0 | так | дальність |
| projectile_speed | number | studs/с | > 0 | ні | швидкість снаряда |
| gravity | number | studs/с² | ≥ 0 | ні | падіння снаряда (рогатка) |
| ricochet | int | — | ≥ 0 | ні | кількість рикошетів |
| multishot | int | — | ≥ 1 | ні | снарядів за постріл |
| crit_chance | number | частка | 0..1 | ні | шанс крита |
| crit_mult | number | множник | ≥ 1 | ні | множник урону крита |
| pellets | int | — | ≥ 1 | ні | дробин за постріл |
| spread | number | градуси | 0..90 | ні | кут конуса дробу |
| falloff_start | number | studs | ≥ 0 | ні | до цієї відстані повний урон дробу |
| falloff_min | number | частка | 0..1 | ні | частка урону дробу на межі `range` |

### weapon_upgrades.json → `weapon_upgrades` (масив)

Прокачка зброї в кімнаті за віспи, діє один забіг.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `<weapon_id>_<upgrade>_<level>` |
| weapon_id | string | — | → `weapons.id` | так | яку зброю качає |
| upgrade | string | — | `damage` / `attack_interval` / `ricochet` / `multishot` / `crit` / `pellets` | так | параметр (`crit` змінює `crit_mult`) |
| order | int | — | ≥ 0 | так | порядок рядка прокачки у вікні |
| level | int | — | ≥ 1 | так | рівень прокачки |
| cost | int | віспи | ≥ 0 | так | ціна цього рівня |
| value | number | як у параметра | — | так | нове значення параметра на цьому рівні |

### run_rewards.json → `run_rewards` (об'єкт)

Нагороди вікна підсумків забігу. Лежить у `rooms/shared/`, кімната може перекрити його **цілим файлом** `rooms/<id>/run_rewards.json` (ключі між файлами не зливаються).

| Поле | Значення |
|---|---|
| `damage_per_soft` | скільки знятого HP ворогів = 1 софт |
| `wisps_per_soft` | скільки невитрачених віспів = 1 софт |
| `base_hp_per_soft` | скільки HP бази, що лишилось, = 1 софт |
| `results_delay` | пауза між кінцем забігу і вікном, с (0..30) |
| `results_timer` | скільки вікно чекає вибору, с (5..300) |
| `damage_dealer_min_players` | стікер «Damage Dealer» лише коли у вікні не менше стільки гравців |
| `wave_soft` | масив: софт за кожну відбиту хвилю по номеру. Довжина має покривати всі хвилі кімнати (валідатор перевіряє) |

## Каталог предметів `items.json`

Одне місце, де живуть **іконка, назва й опис** кожного предмета: валюти, зброя, пастки, бустери, речі. Магазин, нагороди й вікно вибору зброї беруть їх звідси за `id`, а не мають власних копій. Лише EN (локалізація пізніше).

Файл лежить у двох місцях (лобі й кімнати читають різні адреси), копії **побайтно однакові**, це перевіряє `validate.py`. Правити будь-яку, потім скопіювати в другу.

| поле | тип | обов. | що означає |
|---|---|---|---|
| id | string | так | snake_case. Для зброї й пасток збігається з `id` у `weapons.json` / `traps.json`; для бустерів і речей з `reward.id` у магазині; для валют `soft`, `hard`, `wisps` |
| kind | string | так | `currency` / `weapon` / `trap` / `booster` / `item` |
| icon | string | так | `rbxassetid://<число>` або `""` (тоді клієнт показує плейсхолдер «?») |
| title | string | так | назва |
| description | string | так | опис; `{ключ}` підставляється зі `values` |
| values | object | ні | числа для плейсхолдерів у `description` |

Перевірки: кожна зброя й пастка має запис і навпаки; `icon` має правильний формат; кожен `{ключ}` в описі має значення в `values` і навпаки; `reward.id` бустерів і речей у `lobby/shop_*.json` є в каталозі; є записи валют `soft`, `hard`, `wisps`.

Іконки: PNG 512x512 з прозорим фоном лежать у `assets/icons/`. Назви файлів і асетів у Creator Hub за регламентом `MD_<Тип>_<Сутність>_<Імʼя>`: `MD` індекс проєкту (MustDie), `Icon` тип обʼєкта, `Weapon` / `Trap` / `Currency` тип сутності, далі унікальне імʼя в PascalCase (`MD_Icon_Weapon_Bow`, `MD_Icon_Trap_EnergyWall`), роздільник `_`. Завантажити в Roblox (Creator Hub → Assets → Images), взяти Asset ID і вписати в `icon` обох копій як `rbxassetid://<ID>`. Іконки валют `soft` (Coins) і `wisps` теж тут (`MD_Icon_Currency_Coin.png`, `MD_Icon_Currency_Wisp.png`): вони замінюють Frame-и в UI (`CoinIcon`, `WispIcon`). Іконки Robux немає навмисно: це бренд Roblox, окремого лічильника hard-валюти в грі нема.

Поки пакети не підключені до каталогу, назви в `weapons.json` / `traps.json` (`name_en`, `name_uk`) і поля `title`/`description` у `lobby/shop_*.json` лишаються. Коли магазини перейдуть на каталог, ці дублі видаляються.

## Файл `lobby/portals.json`

Порталі лобі. Читає пакет `Portal` (ConfigService, ім'я конфігу `portals`), Place ID у самому пакеті немає.

| Поле | Значення |
|---|---|
| `maxPlayers` | максимум гравців у групі, 1..4 (місця, що лишились вільними, займають боти кімнати) |
| `autoJoinRadius` | радіус у studs: хто стоїть біля порталу, автоматично потрапляє в групу того, хто його відкрив |
| `portals[].id` | рядок, збігається з атрибутом `ContentId` порталу в Studio (`"1"`, `"2"`...) |
| `portals[].title` | назва у вікні порталу |
| `portals[].placeId` | Place ID кімнати; `0` поки кімнати немає |
| `portals[].enabled` | `false` = у вікні «Coming soon», телепорту немає |
| `portals[].maxPlayers` | необов'язково: ліміт саме цього порталу, 1..4 |

У TeleportData кімнати йдуть `teamSize`, `ContentId`, `partyHost`. Нова кімната: додати Place у Experience, вписати рядок у `portals`, поставити `enabled: true`.

## Як додати нову кімнату

1. У Studio продублювати Place `MustDie - Room Template` (Creator Hub: Places → Duplicate) і дати йому ім'я `MustDie - Room N`.
2. Скопіювати `rooms/template/` у `rooms/roomN/` (`N` у snake_case, наприклад `room3`).
3. У `rooms/roomN/room.json` поставити `"id": "roomN"`, змінити числа і спавнери під кімнату. Зони і спавнери назвати так, як на карті (`EnemySpawn` з атрибутом `SpawnerId`).
4. У новому Place в `ReplicatedStorage.RoomProjectConfig` поставити `roomId = "roomN"`, замінити карту (контракт карти: README в `ServerScriptService._README_FOR_CLAUDE`).
5. Додати рядок у `lobby/portals.json` з `placeId` нової кімнати.
6. Прогнати `python3 tools/validate.py`.

## Перед кожним комітом

```
git fetch origin main && git rebase origin/main
python3 tools/validate.py      # має бути "OK"
```

Невеликі коміти з версією балансу в описі (`BAL-0004: waves room1`). Без force push. Не змінюємо `lobby/` і назви/склад полів уже опублікованих файлів без попередження: код написано під них.

## Гілки: main і release

- `main` робоча гілка: сюди коміти, PR, правки балансу. Гра її **не** читає.
- `release` те, що бачать гравці. Усі кімнати й лобі читають `.../release/...`.
- Просування змін у гру: GitHub -> вкладка **Actions** -> **promote-release** -> **Run workflow**. Дія спершу запускає `validate.py` на `main`, і лише якщо все чисто, переносить `release` на поточний `main` (fast-forward, без перезапису історії).
- Після просування сервери підхоплять зміни самі: нові значення читаються кожні `configRefreshSeconds` (зараз 300 с) і застосовуються на початку наступного забігу. Перезапуск серверів не потрібен.
- Відкотити: у `main` зробити `git revert` потрібного коміту і ще раз запустити promote-release.
- Руками (якщо потрібно): `git push origin main:release` (лише після `python3 tools/validate.py`).
