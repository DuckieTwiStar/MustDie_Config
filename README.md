# MustDie_Config

Конфіги гри MustDie (Roblox). Гра читає їх сервером (`CoreServer.ConfigService`) за raw-посиланням:

```
https://raw.githubusercontent.com/DuckieTwiStar/MustDie_Config/main/<папка>/<ім'я>.json
```

Джерело чисел: GDD MustDie, вкладка «Тест балансу». Кожна збережена версія балансу має id `BAL-XXXX`; він стоїть у `meta.version` кожного файлу. Знімок версії лежить також на Google Диску (папка `Balance`).

## Структура

```
lobby/                  конфіги лобі (магазини, щоденні нагороди, лідерборди, портали)
rooms/
  shared/               спільне для всіх кімнат
    rules.json
    enemies.json
    traps.json
    weapons.json
    weapon_upgrades.json
    leaderboards.json   той самий вміст, що lobby/leaderboards.json
  room1/                Room 1 (один спавнер, хвилі на 1 гравця, множники > 1)
    room.json
    zones.json
    waves.json
    players.json
  room2/                Room 2 (два спавнери, хвилі на 4 гравців, множники < 1)
    ...                 ті самі чотири файли
  balance.json          старий зведений файл BAL-0003, гра його не читає; видалимо, коли код перейде на shared/
  leaderboards.json     старе місце, Room 1 читає його до перемикання на shared/
docs/prices.md          ціни лобі: розблокування зброї, розблокування і прокачка пасток
tools/validate.py       перевірка перед комітом
```

Кімната читає кожен конфіг так: спершу `rooms/<roomId>/<ім'я>.json`, якщо його немає (404), то `rooms/shared/<ім'я>.json`, далі вшитий default. Файл кімнати **повністю замінює** спільний, злиття полів немає.

## Правила формату

1. UTF-8, коректний JSON: без коментарів, без кінцевих ком, подвійні лапки.
2. Корінь файлу це об'єкт: `{ "meta": {...}, "<ім'я>": ... }`. Ключ даних збігається з іменем файлу.
3. `meta`: `version` (`BAL-0003`), `exported_at` (дата `YYYY-MM-DD`), `note` (один рядок, що це за файл).
4. Колекції це масиви об'єктів з полем `id`. Числових ключів об'єкта не використовуємо. Порядок задає поле (`order`, `wave`, `level`), а не позиція в масиві.
5. `id`: `snake_case` (малі літери, цифри, `_`), унікальні в межах файлу (у пастках унікальна пара `id` + `level`), стабільні: після публікації не перейменовуються.
6. Числа числами, без одиниць у значенні. Відсутнє значення = відсутній ключ, не `null`. Булеві `true`/`false`.
7. Посилання між файлами за `id`: `waves.enemy_id` → `enemies.id`, `waves.spawner_id` → `room.spawners[].id`, `weapon_upgrades.weapon_id` → `weapons.id`.
8. Тексти для гравця: `name_en`, `name_uk`. Нова мова = новий ключ `name_xx`.
9. Поля, потрібні лише симуляції балансу, сюди не кладемо. Виняток: `zones.length` (див. нижче).
10. Секретів і особистих даних не кладемо: репозиторій публічний.
11. Кожне число з GDD, що впливає на гру, живе в конфігу і ніде більше. Нове число = нове поле тут і рядок у цьому README.
12. Геометрія карти лежить у Place. Зони, спавнери, двері описуються тут лише за `id`; у Place є об'єкти з тим самим `id` в атрибуті або тегу.

### Одиниці

| Величина | Одиниця |
|---|---|
| частки, шанси, броня, множники падіння | частка від 0 до 1 (`0.25` = 25%) |
| час | секунди |
| відстань, радіус, розмір | studs |
| швидкість | studs/с |
| гравітація снаряда | studs/с² |
| кути | градуси |
| ціни в `rooms/` | віспи (валюта забігу; у коді поля зветься `cost`/`reward`/`start_coins`) |

## Файли `rooms/shared/`

### rules.json → `rules` (об'єкт)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| start_coins | int | віспи | ≥ 0 | так | віспи кожного гравця на старті забігу |
| refund_share | number | частка | 0..1 | так | яка частка віспів повертається за знесену пастку |
| reward_mode | string | — | `each` / `split` / `killer` | так | хто отримує віспи за вбивство: кожен повністю / поділ / лише вбивця |
| ricochet_falloff | number | частка | 0..1 | так | частка урону, що лишається після кожного рикошету |
| cell_size | number | studs | > 0 | так | розмір клітинки сітки пасток |
| restart_delay | number | с | ≥ 0 | так | пауза після кінця забігу перед рестартом |

### enemies.json → `enemies` (масив)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `grunt`, `warrior`, `brute` |
| name_en, name_uk | string | — | — | так | назва для гравця |
| size | string | — | `small` / `medium` / `large` | так | клас розміру |
| hp | number | — | ≥ 1 | так | здоров'я |
| speed | number | studs/с | > 0 | так | швидкість руху |
| armor | number | частка | 0..0.95 | так | яку частку урону зрізає броня |
| damage_to_base | number | — | ≥ 0 | так | урон печатці, коли ворог доходить |
| reward | int | віспи | ≥ 0 | так | віспи за вбивство (за `reward_mode`) |

### traps.json → `traps` (масив, рядок на пару `id` + `level`)

Розблокування і рівень пастки зберігаються в профілі гравця (купуються в лобі, ціни в `docs/prices.md`). У кімнаті пастки лише встановлюються.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `snare`, `energy_wall`, `turret`; збігається з `id` предмета в магазині лобі |
| level | int | — | 1..N без пропусків | так | рівень пастки |
| order | int | — | ≥ 0 | так | порядок у вікні пасток (менше = раніше) |
| name_en, name_uk | string | — | — | так | назва |
| mechanic | string | — | `snare` / `wall` / `turret` | так | тип механіки |
| placement | string | — | `floor` / `wall` | так | куди ставиться |
| cost | int | віспи | ≥ 0 | так | ціна **встановлення** пастки цього рівня в кімнаті |
| damage | number | за удар; для `wall` за секунду | ≥ 0 | так | урон |
| cooldown | number | с | ≥ 0 | ні | перезарядка капкана |
| hold_time | number | с | ≥ 0 | ні | скільки капкан тримає ворога |
| fire_interval | number | с | > 0 | ні | інтервал пострілів турелі |
| range | number | studs | ≥ 0 | ні | радіус турелі |
| default_owned | bool | — | — | ні | `true` на рівні 1 пастки, яка є в усіх без покупки |

### weapons.json → `weapons` (масив)

Розблокування зброї в профілі гравця (лобі, ціни в `docs/prices.md`). Перед забігом гравець обирає зброю зі своїх наявних.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | збігається з `id` предмета в магазині лобі |
| order | int | — | ≥ 0 | так | ранг: більше = вище у вікні вибору перед забігом; у магазині лобі навпаки; слоти клавіш 1..N від меншого до більшого |
| default_owned | bool | — | — | ні | `true` = є в усіх без покупки |
| name_en, name_uk | string | — | — | так | назва |
| damage | number | — | ≥ 0 | так | урон за удар/постріл (дробовик: за одну дробину) |
| attack_interval | number | с | > 0 | так | пауза між атаками |
| range | number | studs | ≥ 0 | так | дальність |
| projectile_speed | number | studs/с | > 0 | ні | швидкість снаряда |
| gravity | number | studs/с² | ≥ 0 | ні | падіння снаряда (рогатка) |
| ricochet | int | — | ≥ 0 | ні | кількість рикошетів |
| multishot | int | — | ≥ 1 | ні | снарядів за постріл |
| crit_chance | number | частка | 0..1 | ні | шанс крита |
| crit_mult | number | множник | ≥ 1 | ні | множник урону крита |
| pellets | int | — | ≥ 1 | ні | дробин за постріл |
| spread | number | градуси | 0..90 | ні | кут конуса дробу |
| falloff_start | number | studs | ≥ 0 | ні | до цієї відстані повний урон дробу |
| falloff_min | number | частка | 0..1 | ні | частка урону дробу на межі `range` |

### weapon_upgrades.json → `weapon_upgrades` (масив)

Прокачка зброї в кімнаті за віспи, діє один забіг.

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `<weapon_id>_<upgrade>_<level>` |
| weapon_id | string | — | → `weapons.id` | так | яку зброю качає |
| upgrade | string | — | `damage` / `attack_interval` / `ricochet` / `multishot` / `crit` / `pellets` | так | параметр (`crit` змінює `crit_mult`) |
| order | int | — | ≥ 0 | так | порядок рядка прокачки у вікні |
| level | int | — | ≥ 1 | так | рівень прокачки |
| cost | int | віспи | ≥ 0 | так | ціна цього рівня |
| value | number | як у параметра | — | так | нове значення параметра на цьому рівні |

## Файли кімнати `rooms/<roomId>/`

### room.json → `room` (об'єкт)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | = назва папки | так | `room1` |
| name_en, name_uk | string | — | — | так | назва кімнати |
| base_hp | number | — | ≥ 1 | так | здоров'я печатки |
| door_timer | number | с | ≥ 0 | так | час фази дверей до першої хвилі |
| spawners | масив | — | — | так | спавнери: `id` (у Place об'єкт з тим самим `id`), `mode` (`simultaneous`), `cooldown` (с) |

### zones.json → `zones` (масив)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | зона маршруту; у Place об'єкт з тим самим `id` |
| order | int | — | ≥ 0 | так | порядок від спавнера до бази |
| name_en, name_uk | string | — | — | так | назва |
| length | number | studs (умовно) | ≥ 0 | так | довжина для симуляції балансу і ботів; гра бере геометрію з Place. **Ще не звірено з картами** |
| spawner_id | string | — | → `room.spawners[].id` | ні | зона належить гілці цього спавнера. Зони без `spawner_id` спільні: ними йдуть вороги з усіх спавнерів. Якщо спавнерів кілька, у кожного має бути своя гілка |

### waves.json → `waves` (масив, рядок на групу ворогів)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `w<номер>_<enemy_id>` |
| wave | int | — | ≥ 1 | так | номер хвилі |
| spawner_id | string | — | → `room.spawners[].id` | так | звідки йдуть |
| enemy_id | string | — | → `enemies.id` | так | який ворог |
| count | int | — | ≥ 1 | так | скільки ворогів до множника `players.count_mult` (Room 1 рахує хвилі на 1 гравця, Room 2 на 4) |
| spawn_interval | number | с | ≥ 0 | так | інтервал між ворогами групи |
| wave_delay | number | с | ≥ 0 | так | пауза перед хвилею; однакова в усіх рядках хвилі |
| min_players | int | — | 1..4 | ні | рядок діє лише для команди від N учасників (гравці + боти). Без поля діє завжди |

### players.json → `players` (масив)

| поле | тип | одиниці | діапазон | обов. | що означає |
|---|---|---|---|---|---|
| id | string | — | snake_case | так | `p1`..`p4` |
| players | int | — | 1..4 | так | кількість гравців (потрібні всі чотири рядки) |
| hp_mult | number | множник | > 0 | так | множник HP ворогів |
| count_mult | number | множник | > 0 | так | множник кількості ворогів у хвилях |
| reward_mult | number | множник | ≥ 0 | так | множник віспів за вбивство |

## Файл `lobby/portals.json`

Порталі лобі. Читає пакет `Portal` (ConfigService, ім'я конфігу `portals`), Place ID у самому пакеті немає.

| Поле | Значення |
|---|---|
| `maxPlayers` | максимум гравців у групі, 1..4 (місця, що лишились вільними, займають боти кімнати) |
| `autoJoinRadius` | радіус у studs: хто стоїть біля порталу, автоматично потрапляє в групу того, хто його відкрив |
| `portals[].id` | рядок, збігається з атрибутом `ContentId` порталу в Studio (`"1"`, `"2"`...) |
| `portals[].title` | назва у вікні порталу |
| `portals[].placeId` | Place ID кімнати; `0` поки кімнати немає |
| `portals[].enabled` | `false` = у вікні «Coming soon», телепорту немає |
| `portals[].maxPlayers` | необов'язково: ліміт саме цього порталу, 1..4 |

У TeleportData кімнати йдуть `teamSize`, `ContentId`, `partyHost`. Нова кімната: додати Place у Experience, вписати рядок у `portals`, поставити `enabled: true`.

## Як додати нову кімнату

1. Скопіювати `rooms/room1/` у `rooms/roomN/` (`N` у snake_case, наприклад `room2`).
2. У `room.json` поставити `"id": "roomN"`, змінити значення під кімнату. Зони і спавнери назвати так само, як об'єкти в Place нової кімнати.
3. Прогнати `python3 tools/validate.py`.
4. Повідомити стороні Жені: у новому Place треба прописати `roomUrl = .../rooms/roomN`.

## Перед кожним комітом

```
git fetch origin main && git rebase origin/main
python3 tools/validate.py      # має бути "OK"
```

Невеликі коміти з версією балансу в описі (`BAL-0004: waves room1`). Без force push. Не змінюємо `lobby/`, `rooms/leaderboards.json` і назви/склад полів уже опублікованих файлів без попередження: код написано під них.
