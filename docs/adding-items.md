Для агента Степанова. Дата: 16.10.2026. Автор: Claude (сторона Жені, пакети/лобі/Room 1).

Це продовження `config-instruction-for-room-agent.md` (загальні правила JSON, shared/room, формат). Тут лише одне: **що саме треба зробити, щоб нова зброя, пастка чи ворог з'явилися в грі та в UI**.

## 1. Де що лежить

| Що | Файл | Хто читає | Про що |
|---|---|---|---|
| Іконка, назва, опис | `rooms/shared/items.json` **і** `lobby/items.json` | UI (HUD, магазини, вікно вибору зброї) | одне джерело для тексту й картинки |
| Характеристики зброї | `rooms/shared/weapons.json` | кімната | урон, інтервал, дальність тощо |
| Характеристики пасток | `rooms/shared/traps.json` | кімната | рядок на пару (`id`, `level`) |
| Прокачка зброї в забігу | `rooms/shared/weapon_upgrades.json` | кімната | рівні й ціни у віспах |
| Ціни лобі (софт) | `price_soft` у `weapons.json` / `traps.json` | лобі (після підключення) | розблокування зброї й прокачка пасток, одне джерело |
| Вороги | `rooms/shared/enemies.json` | кімната | hp, швидкість, нагорода |

Принцип: **числа балансу в `weapons/traps/enemies`, лише текст і картинка в `items.json`**. Текст з двох місць не дублюємо.

## 4. Рецепт: нова зброя

1. **`rooms/shared/weapons.json`**: додай об'єкт у `weapons`.
   - `id`: `snake_case`, унікальний, **не міняти після публікації**.
   - `order`: ціле. Більше значення = вище в списку вибору. Зараз: кулаки 10, рогатка 20, лук 30, дробовик 40. Новій зброї став значення між сусідами (наприклад 35) або вище 40. Крок 10 не обов'язковий, але лишай просвіти.
   - обов'язкові: `damage`, `attack_interval` (с), `range` (студи). Решта полів з наявних (`projectile_speed`, `pellets`, `spread`, `ricochet`, `crit_chance` тощо), як у лука або дробовика.
   - `tier`: ціле від 1. Прогрес: від нього залежать замки порталів і зброя ботів. Не спадає з `order` серед базової зброї (бо дорожча/сильніша = вищий tier).
   - `price_soft`: ціна розблокування в лобі (ціле > 0). Обов'язкова для кожної базової зброї, і для `default_owned` теж: гравець не платить, але ціна задає бюджет ботів. Модифікація ціни не має.
   - `default_owned: true` лише якщо зброя доступна всім без покупки.
   - `name_en` і `name_uk` **поки обов'язкові** (валідатор вимагає). Це тимчасовий дубль з `items.json`: коли ми переведемо UI на каталог, ці поля приберемо.
2. **`rooms/shared/items.json`**: додай у `items` рядок:
   ```json
   {
     "id": "<той самий id>",
     "kind": "weapon",
     "icon": "rbxassetid://<ID>",
     "title": "Crossbow",
     "description": "Slow, heavy bolts that pierce armor."
   }
   ```
   Англійською (локалізацію робимо пізніше). Опис коротко, одне-два речення, без чисел, які можуть змінитися. Якщо число в описі потрібне, див. розділ 7 (плейсхолдери).
3. **Скопіюй той самий файл у `lobby/items.json`** (побайтно однаковий): `cp rooms/shared/items.json lobby/items.json`.
4. Ціна вже в `price_soft` (окремого файлу цін більше немає). Подивись `python3 tools/validate.py --economy`: що це змінює для ботів.
5. Якщо зброя має прокачку в забігу: рядки в `weapon_upgrades.json` (`weapon_id` = твій `id`).
6. `python3 tools/validate.py`. Має бути `OK`.
7. Коміт у `main` (див. розділ 9).

## 5. Рецепт: нова пастка

Пастка в `traps.json` це **рядок на кожну пару (`id`, `level`)**. У `items.json` пастка одна на `id`, без рівнів.

1. **`rooms/shared/traps.json`**: рівні 1..N, на кожен окремий об'єкт.
   - спільні для рівнів поля повтори в кожному рядку (`order`, `name_en`, `name_uk`, `mechanic`, `placement`, `cost`);
   - `mechanic`: `snare` / `wall` / `turret`. **Нова механіка (новий тип поведінки) це код, і перелік у валідаторі розширюють ми.** Якщо твоя пастка поводиться як наявна, використай її `mechanic`;
   - `placement`: `floor` або `wall`;
   - `cost` це віспи за **встановлення** в кімнаті; ціни лобі йдуть у `price_soft` (окремо від `cost`);
   - `price_soft`: ціна цього рівня в лобі. Рівень 1 = 0, якщо пастка є в усіх (`default_owned: true`, лише на рівні 1), інакше > 0. Рівні вище завжди > 0.
2. **`items.json`** (обидві копії): один рядок `kind: "trap"` з тим самим `id`.
3. Ціни вже в `price_soft` рядків. Окремої таблиці цін немає.
4. Перевірка й коміт, як у розділі 4.

## 6. Іконки

- PNG **512x512**, прозорий фон, об'єкт по центру з невеликим відступом до краю. Стиль як у наявних (`assets/icons/`): читається на малому розмірі, без тексту.
- Файл у репо: `assets/icons/MD_Icon_<Weapon|Trap|Currency>_<UniqueName>.png`, ім'я PascalCase: `MD_Icon_Weapon_Crossbow.png`, `MD_Icon_Trap_SpikePit.png`.
  - `_` роздільник, `MD` індекс проєкту, `Icon` тип обʼєкта, далі тип сутності, далі унікальне імʼя.
- Завантаження: Creator Hub → Assets → Images, **та сама назва, що й файл (без `.png`)**. Беремо **Asset ID** (число) і вписуємо `icon: "rbxassetid://<ID>"` в обох копіях `items.json`.
  - Завантажує власник групи/Experience (Женя) або той, хто має право додавати Images до групи. Якщо в тебе немає доступу, поклади PNG у репо, залиш `icon: ""` і напиши Жені: ми завантажимо й вставимо ID.
- Порожній `icon: ""` це не помилка: клієнт покаже плейсхолдер. Але в реліз із порожніми іконками зброї й пасток не йдемо.
- Іконка Robux не потрібна (бренд Roblox).

## 7. Опис з числами (плейсхолдери)

Якщо в описі треба число, пиши `{ключ}` і додай `values`:
```json
{ "id": "shield", "kind": "item", "icon": "", "title": "Shield",
  "description": "Absorbs {hits} hits.", "values": { "hits": 3 } }
```
Валідатор вимагає, щоб кожен `{ключ}` мав значення в `values` і навпаки. Для зброї й пасток числа балансу краще **не** дублювати в описі: вони можуть змінитися в `weapons.json`, а текст застаріє.

## 8. Вороги: каталог

Назва, опис і портрет ворога живуть у `items.json` з `kind: "enemy"`, числа (hp, швидкість, нагорода) лишаються в `enemies.json`. Навіщо: назва потрібна в UI (прев'ю хвилі, бестіарій, повідомлення про боса), і зараз вона дублюється в `name_en` / `name_uk` в `enemies.json`.

**Рядки `kind: "enemy"` не додавай, поки Женя не підтвердить, що пакет Core з типом `enemy` опубліковано.** Інакше гра відкине весь `items.json` (невідомий `kind` ламає перевірку файлу цілком) і втратить іконки валют. Валідатор (`validate.py`) уже знає тип `enemy`: щойно в каталозі з'являється перший запис ворога, він вимагає записи для всіх ворогів з `enemies.json` і навпаки.

Коли можна: рядок у `enemies.json` (числа), рядок `kind: "enemy"` в обох копіях `items.json` (назва, опис, портрет 512x512 з ім'ям `MD_Icon_Enemy_<Name>`), модель у Place (наша частина). `name_en` / `name_uk` з `enemies.json` приберемо, коли UI перейде на каталог.

Поки не підтверджено: новий ворог це рядок у `enemies.json` + модель у Place, без запису в `items.json`.

## 9. Перед комітом

```
git fetch origin main && git rebase origin/main
python3 tools/validate.py      # має бути "OK: усі конфіги валідні"
```

Валідатор перевіряє зокрема: кожна зброя й пастка має запис в `items.json` і навпаки; формат `icon`; плейсхолдери; **обидві копії `items.json` побайтно однакові**.

- Коміт у `main`, невеликі, з версією балансу в описі (`BAL-0004: crossbow`). Без force push.
- **Гра читає лише `release`.** Просування з `main` в `release` робить workflow `promote-release` (GitHub → Actions → Run workflow). Запускай його після узгодження з Женею: нова зброя без коду нічого не змінює в грі, але збірку релізу вирішує Женя.
- Не змінюй `id`, що вже опубліковані, і не прибирай поля без повідомлення нам.
