# Пауза між хвилями і бонус віспів (В-011, 04.11.2026, Агент J)

Мета: чітко розділити стадії забігу для гравця: бій → зачистка (бонус віспів) → пауза 15 с (будуємо, купуємо) → наступна хвиля.

## Поля
- `rules.run.wave_clear_pause` (с, 0 = вимкнено). Наступна хвиля стартує пізніше з двох: кінець спавну попередньої + `wave_delay` її рядків, або зачистка + `wave_clear_pause`. Зачистка = у кімнаті немає живих ворогів. Старий режим (0): лише `wave_delay` від кінця спавну.
- `rules.run.wave_clear_timeout` (с, 90; 0 = без ліміту): запобіжник. Якщо від кінця спавну минуло стільки, а живі вороги ще є (застряг), хвиля вважається не зачищеною: бонусу немає, `warn` у консолі «[Wave] хвиля N: зачистки немає … » зі списком застряглих (id, s, позиція), далі пауза `wave_clear_pause` і наступна хвиля.
- `rooms/<room>/run_rewards.json` → `wave_wisps`: бонус віспів кожному учаснику за хвилю N, видається в момент зачистки. 0 або відсутнє = без бонусу.
- `waves.json` → `wave_delay` Room 1: 15 для хвиль 2+ (працює і в старому режимі).
- `min_players` у рядках остання хвилі Room 1: для 1 гравця лише `gatekeeper`; решта рядків діють від 2 учасників. Валідатор вимагає, щоб у кожній хвилі для 1..4 гравців був хоч один рядок.

## Клієнт
`State`: `BreakUntil` (серверний час старту наступної хвилі, 0 = не пауза), `WaveBonusSerial` (лічильник), `WaveBonusAmount`, `WaveBonusWave`. HUD показує «NEXT WAVE m:ss» у блоці події і тост «WAVE BONUS +N» (`Client.WaveBonusClient`).

## Сумісність
Старі Packages ігнорують `wave_clear_pause` і `wave_wisps` (невідомі ключі), тож `release` з новими конфігами безпечний: лишається пауза 15 с від кінця спавну без бонусу. Бонус і «NEXT WAVE» потребують Packages збірки 2026-11-04.5+ (запобіжник — 2026-11-04.7+).
