## Принципи

1. **Ефект це запис у конфігу.** Числа, стакання, модифікатори, теги, переходи в JSON. Код знає лише фіксований словник (нижче).
2. **Стану як окремої сутності немає.** Стан це ефект, що видає тег (`frozen`). Умови це лише теги й кількість стеків.
3. **Модифікатори рахує один обчислювач.** Швидкість, вхідний урон, урон з часом беруться зі стеків усіх активних ефектів, а не з окремого коду на ефект.
4. **Хто наклав, той і відповідає.** Бали, вбивство й нагорода діляться між тими, хто наклав стеки.
5. **Міграція не змінює геймплей.** Чотири наявні ефекти переходять у нову схему з тими самими числами.

## Модель

| Поняття | Що це |
|---|---|
| **Ефект** | запис у `status_effects.json`: тип, стекінг, модифікатори, теги, переходи |
| **Накладання** | один виклик `apply`: ефект, джерело (гравець), `stacks`, за потреби числа джерела |
| **Модифікатор** | число, яке активні ефекти змінюють на ворогові (швидкість, вхідний урон, урон з часом) |
| **Тег** | рядок, що його видає ефект (`frozen`, `held`); умови читають теги |
| **Стан** | ефект з тегом, який вмикається переходом (`chill` на порозі дає `frozen`) |

### Стекінг

- `max_stacks` (1 за замовчуванням).
- **`max_stacks = 1`: ефект із таймером.** Поле `duration` (с; 0 = до зняття або смерті). Повторне накладання за `reapply`: `refresh` (таймер з нуля) або `ignore` (нічого, як було в В-001). Типово `refresh`.
- **`max_stacks > 1`: лічильник стеків.** Нове накладання додає `stacks`, не більше `max_stacks`. Один стек згасає кожні `decay_interval` секунд (0 = не згасає). Ефект діє, поки стеків більше 0. Таймера `duration` немає.
- **Сила накладання лише через `stacks`.** Числа джерела (див. нижче) перекривають значення тільки в ефектів з `max_stacks = 1`. У лічильника всі стеки однакові, значення йдуть з конфігу ефекту.
- **Внесок джерел.** Для кожного ефекту на ворогові ведеться таблиця «гравець → кількість стеків». Урон ефекту ділиться між гравцями пропорційно, бали й вбивство йдуть кожному за його частку.

### Модифікатори

Поле `modifiers` ефекту: масив `{ stat, value, per_stack, requires_tags }`.

- `per_stack` (false за замовчуванням): значення множиться на кількість стеків (`add`) або береться в степені стеків (`mul`).
- `requires_tags`: модифікатор діє лише поки на ворогові є всі ці теги.

Словник `stat` і правило об'єднання (`combine`) лежать у `status_effects.json` у секції `stats`, не в коді:

| `stat` | `combine` | базове | Що означає |
|---|---|---|---|
| `speed_mult` | `min` | 1 | множник швидкості руху (0 = стоїть); береться найсильніший (найменший) |
| `damage_taken_mult` | `max` | 1 | множник усього вхідного урону; береться найбільший |
| `damage_taken_mult.<тип>` | `max` | 1 | те саме лише для типу урону (`fire`, `shock`, `ice`, `physical`) |
| `dps` | `add` | 0 | урон за секунду (число); сума по ефектах |
| `hp_pct_per_sec` | `add` | 0 | урон за секунду як частка максимального HP ворога (0.005 = 0,5%) |

Усі модифікатори одного `stat` мають один `combine` (валідатор перевіряє за секцією `stats`). Підсумок `speed_mult` і `damage_taken_mult` обмежується діапазоном зі `stats` (`min`/`max` у секції).

Для `dps` і `hp_pct_per_sec` ефект може вказати `damage_type` (за замовчуванням `physical`) і `armor_pierce` (0..1, 0 за замовчуванням): так само, як у зброї.

### Теги

- Ефект видає теги: `grants_tags`. Ворог має тег, поки активний хоча б один ефект, що його видає.
- Умови: `requires_tags` ефекту (накладається, лише якщо ворог має всі) і `blocked_by_tags` (не накладається, якщо є хоча б один). Модифікатор теж може мати `requires_tags`.
- Теги ворога з `enemies.json` (`tags`, наприклад `boss`) додаються пізніше, на етапі 7 (поле `tags` у схемі ворога поки немає, додамо тоді).

### Переходи (події ефекту)

| Подія | Коли | Поле |
|---|---|---|
| `on_max_stacks` | лічильник дійшов до `max_stacks` | `{ "consume": true, "apply": "<id>", "stacks": n, "duration": d }` |
| `on_end` | ефект закінчився сам (таймер вийшов, згас останній стек); не при споживанні й не при смерті | `{ "apply": "<id>", ... }` |
| `on_death` | ворог помер, поки ефект діяв | `{ "blast": { "damage", "radius", "damage_type", "armor_pierce", "fx", "sound" } }` |

- `consume: true` скидає стеки, лише якщо `apply` вдався (або `apply` не заданий). Якщо ціль заблокована тегом (наприклад, імунітет після `frozen`), стеки лишаються на максимумі, а наступне накладання пробує перехід знову.
- `apply` у подіях накладає ефект від головного джерела (гравця з найбільшим внеском у ефект, що спрацював). Внесок самого нового ефекту починається з нього одного.
- Цикли (`A` дає `B`, `B` дає `A`) валідатор забороняє.

Словник дій фіксований: `consume`, `apply`, `blast`. Усе складніше це код (і окрема домовленість).

## Схема `status_effects.json`

Секції: `stats` (словник модифікаторів, таблиця вище) і `status_effects` (рядки):

| Поле | Тип | Опис |
|---|---|---|
| `id`, `name_en`, `name_uk` | рядки | як зараз |
| `max_stacks` | int ≥ 1 | 1 = таймер, більше = лічильник |
| `duration` | с | для `max_stacks = 1`; 0 = до зняття або смерті |
| `decay_interval` | с | для лічильника: час згасання одного стека (0 = не згасає) |
| `reapply` | `refresh` \| `ignore` | для `max_stacks = 1`, типово `refresh` |
| `modifiers` | масив | див. вище |
| `damage_type`, `armor_pierce` | | для `dps` і `hp_pct_per_sec` |
| `tick` | с | як часто нараховується урон `dps` і `hp_pct_per_sec` (0.25 за замовчуванням) |
| `grants_tags`, `requires_tags`, `blocked_by_tags` | масиви рядків | теги |
| `on_max_stacks`, `on_end`, `on_death` | об'єкти | переходи |
| `visual` | рядок | вигляд на ворогові (зараз `fire`); решту візуалу ведуть Вася й Агент Коричневий |

## Міграція чотирьох ефектів (геймплей не міняється)

Поле `kind` (`dot`, `stun`, `slow`, `death_blast`) зникає: механіку тепер задають модифікатори й події.

```json
{ "id": "burn", "max_stacks": 1, "duration": 3, "reapply": "ignore", "tick": 0.25,
  "damage_type": "fire", "visual": "fire",
  "modifiers": [ { "stat": "dps", "value": 10 } ] },
{ "id": "stun", "max_stacks": 1, "duration": 1.5, "reapply": "ignore",
  "grants_tags": ["held"],
  "modifiers": [ { "stat": "speed_mult", "value": 0 } ] },
{ "id": "slow", "max_stacks": 1, "duration": 2, "reapply": "ignore",
  "modifiers": [ { "stat": "speed_mult", "value": 0.5 } ] },
{ "id": "ash_curse", "max_stacks": 1, "duration": 0, "reapply": "ignore",
  "on_death": { "blast": { "damage": 100, "radius": 8, "damage_type": "fire",
                           "armor_pierce": 1, "fx": "ash", "sound": "ash_boom" } } }
```

**Числа джерела.** Джерело (`on_hit` зброї чи пастки) передає ключі: `chance`, `stacks`, `duration` і назви змінних значень: ім'я `stat` модифікатора (`dps`, `speed_mult`) або поле блоку (`damage`, `radius` для `blast`). Це зберігає поточні ключі `on_hit.burn.dps`, `on_hit.stun.duration`, `on_hit.ash_curse.damage`, а також прокачки (`stat: on_hit.burn.dps`). Для лічильника діє лише `stacks`.

## Приклад нового контенту (холод і заморозка)

```json
{ "id": "chill", "max_stacks": 5, "decay_interval": 2,
  "damage_type": "ice",
  "blocked_by_tags": ["frozen"],
  "modifiers": [
    { "stat": "speed_mult", "value": 0.8 },
    { "stat": "hp_pct_per_sec", "value": 0.005, "per_stack": true } ],
  "on_max_stacks": { "consume": true, "apply": "frozen" } },
{ "id": "frozen", "duration": 3, "max_stacks": 1, "reapply": "ignore",
  "grants_tags": ["frozen"], "blocked_by_tags": ["frozen_immune"],
  "modifiers": [
    { "stat": "speed_mult", "value": 0 },
    { "stat": "damage_taken_mult.shock", "value": 1.5 } ],
  "on_end": { "apply": "frozen_immune" } },
{ "id": "frozen_immune", "duration": 4, "max_stacks": 1, "reapply": "ignore",
  "grants_tags": ["frozen_immune"] }
```

Пастка накладає холод так: `"on_hit": { "chill": { "stacks": 2 } }` (кількість стеків залежить від рівня пастки з лобі, окремого поля не потрібно). Вогонь на заморожену ціль, мітка чи отрута додаються рядками без коду.

## Конвеєр урону

`EnemyService.damage(ворог, число, джерело, kind, armorPierce, damageType)`: додаємо шостий параметр `damageType` (`physical` за замовчуванням). Порядок:

1. число × `damage_taken_mult` (усі джерела) × `damage_taken_mult.<тип>`;
2. броня з урахуванням `armor_pierce`;
3. HP і бали (як зараз, лише фактично знятий HP).

Урон ефектів (`dps`, `hp_pct_per_sec`) іде тим самим конвеєром зі своїм `damage_type` і з розподілом між гравцями за внеском. Типи урону: `physical`, `fire`, `shock` і новий `ice` (додаємо у валідатор і зброю).

## Код і API

- `EffectService.apply(ворог, id, гравець, { stacks, duration, <числа джерела> })` лишається, повертає `true`, якщо щось змінилось (накладено чи додано стеки).
- Нові: `EffectService.stacks(ворог, id)`, `EffectService.hasTag(ворог, тег)`.
- `EffectService.has`, `remove`, `list` лишаються.
- Підсумкові модифікатори перераховуються при кожній зміні (накладання, згасання, кінець): `enemy.speedMult`, `enemy.takenAll` (усі типи), `enemy.takenByType[тип]`, `enemy.effectTags` і `enemy.heldUntil` (час кінця, поки швидкість 0; для капкана й клієнта). `EnemyService` читає лише ці поля й не залежить від `EffectService`.
- Крок за кадром проходить усіх ворогів, але миттєво пропускає тих, у кого немає ефектів.
- Для джерел: `EffectService.isDot(id)` (ефект дає урон з часом) і `EffectService.hasBlast(id)`. Зброя не накладає порожній ефект: якщо в `on_hit` число `dps` чи `damage` дорівнює 0, ефект вимикається (його вмикає прокачка). Число `armorPierce` джерела (вуду: 1) перекриває `armor_pierce` ефекту з таймером.
- `TrapService` при знищенні капкана знімає оглушення (`EffectService.remove(ворог, "stun")`) і читає `heldUntil`.
- Старий формат JSON (поле `kind`) валідатор відхиляє: гра бере вбудовані значення, які збігаються з міграцією. Тому код можна публікувати до злиття JSON і навпаки.

## Що бачить клієнт (Вася й Агент Коричневий)

На хітбоксі ворога:

| Атрибут | Значення |
|---|---|
| `Effect_<id>` | серверний час кінця; `-1` = діє, поки є стеки або до смерті; `0` = немає (як зараз) |
| `Stacks_<id>` | кількість стеків (для лічильника) |
| `Tags` | теги ворога через кому (`frozen,held`) |
| `HeldUntil` | лишається для анімації капкана (час кінця, поки швидкість 0) |

Візуал за кількістю стеків (колір, пули над ворогом) домовляємо з Васею окремо, до публікації нового ефекту в грі.

## Обмеження першої версії

- Теги й опори ворогів (`status_resist`, `immune`) на етапі 7, але формат вище їх не блокує.
- Реакції типу «вогонь по замороженому» зводяться до `requires_tags` у модифікаторах. Окремого шару реакцій не робимо, поки не покаже плейтест.
- Максимум стеків і порогових переходів за ефект: один `on_max_stacks`. Ланцюг із двох і більше станів будуємо через `on_end`.
- Урон у відсотках HP на босах: правило (чи ігнорує броню, чи діє множник опору) вирішуємо на етапі 7 разом із `status_resist`.
