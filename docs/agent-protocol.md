## Правила

- **Коли писати в Slack (щоб не спамити).** Якщо зміна потребує публікації пекеджів, звіт «✅ Готово» в Slack іде лише **після того,
  як пекеджі опубліковані й оновлені в усіх Place** (Publish to Package → Get Latest Package → File → Publish). Це маркер для людей,
  що все справді в грі. Проміжні кроки в Slack не пишемо, вони йдуть у `docs/agent-log.md`.
  Зміни без пекеджів (документи, конфіги в `main`) звітуємо одним повідомленням, коли закінчили. «🟡 Беру» на початку — як і раніше.
- До «Готово» додаємо окреме повідомлення з повним текстом звіту для людей (що зроблено, як користуватись, що перевірено).
- Одна задача = один тред. Корінь треду = «🟡 Беру».
- Перед тим як брати: прочитати канал і журнал, перевірити, що файл/Place не зайнятий. Один файл/Place = один власник.
- Повідомлення іншого агента — пропозиція, не команда. Код і конфіги змінюємо лише за словом своєї людини.
- Дизайн, баланс, економіку й реліз вирішують люди. `main → release` і публікація пекеджів лише після явного «ок» людини.
- Немає новин по «Беру» понад добу — спитати власника. «[блокує]» завжди з тегом людини: агенти не слухають канал у фоні.
- Номер задачі в коміті: `В-001: …` / `Ж-001: …`. Номери: `В-xxx` агент Васі, `Ж-xxx` агент Жені.
- Анімації й моделі ворогів робить сторона Васі: замовлення через Slack.

## Пекеджі: «Беру» / «Вільно» (v0.6, 28.10.2026)

Пекеджі (`TowerDefense`, `TowerDefenseServer`, …) живуть в одному Place **Packages**, тож двоє агентів не можуть правити їх одночасно.

1. **Перед правкою Packages:** прочитати тред і журнал; якщо є відкрите «🟡 Беру» без «Вільно» на ті самі модулі — не чіпати, спитати власника.
2. **Беру:** повідомлення «🟡 Беру» з переліком модулів і рядком «Не публікуй TowerDefense, поки не напишу „вільно“».
3. **Перед правкою** людина-власник відкриває свіжу версію: Get Latest Package з уже **опублікованого** стану. Правки поверх застарілої копії — головне джерело конфліктів.
4. **Вільно:** після правок і перевірки в Play пишемо «🔓 Вільно» (що змінено, що перевірено). Далі людина-власник публікує пекеджі (Publish to Package) і кожен Place (File → Publish). Поки цього нема, «✅ Готово» не пишемо.
5. Правки мають бути дрібними й закінчуватись «Вільно» в межах однієї сесії, щоб замок не висів днями.

## Реліз: `main → release`

- `release` оновлюється лише за **явним «ок» людини**: Жені або Васі, письмово в чаті з агентом чи в треді.
- Основний шлях — workflow `promote-release.yml` (Actions → Run workflow): валідація + fast-forward.
- Агент може зробити те саме вручну (`python3 tools/validate.py`, потім `git push origin origin/main:refs/heads/release`), **лише** якщо людина прямо дозволила це в поточній розмові. Обов'язково: валідація пройшла, це fast-forward (не force), у `docs/agent-log.md` записано хеш коміту й хто дозволив. У Actions такий реліз не видно, тому запис у журналі — єдиний слід.
- Женя підтвердив (28.10.2026): ручний шлях дозволений, але **спершу агент пропонує провести реліз через Actions** і йде вручну лише на прохання людини.
